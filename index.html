Comment je travaille

Diagnostiquer, prototyper, déployer, faire adopter, mesurer

La même boucle sur chaque projet. Les exemples viennent tous de la plateforme transport, sauf mention contraire.

Diagnostiquer

Partir de ce qui existe : classeurs Excel ressaisis chaque semaine, workflows n8n fragiles, papiers signés. Je liste qui saisit quoi, et où l'erreur coûte cher (la paie).

Prototyper

Une version autonome et petite d'abord. Le formulaire de signalement de défaut véhicule a d'abord existé comme application autonome, puis a été intégré à la plateforme.

Déployer

Une PR par changement, des tests garde-fous, et un ordre de mise en production pensé pour éviter la coupure : la plateforme envoie le jeton du MCP avant que le serveur ne l'exige.

Faire adopter

Des écrans par rôle, utilisables au téléphone sur le terrain. Un rôle en lecture seule pour la RH, un rôle atelier limité aux signalements. Chacun voit ce dont il a besoin.

Mesurer

Compteurs de tournées réalisées et oubliées, alerte chaque matin si une tournée n'est pas saisie, journal de chaque alerte envoyée. Ce qui n'est pas mesuré se dégrade sans bruit.

Avec Claude Code comme agent de développement

Je travaille avec Claude Code comme on travaille avec un développeur : je fixe le besoin, les contraintes et les critères d'acceptation, il propose, je relis et je tranche. Sur la plateforme transport, 488 des 707 commits sont co-signés avec Claude, toujours passés par une PR et des tests.

Ce qui fait la différence n'est pas l'outil mais le cadrage : des règles écrites dans le dépôt (une branche et une PR par changement, jamais de donnée réelle dans un test) et des tests qui protègent ce qui a déjà cassé une fois.
